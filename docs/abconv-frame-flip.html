abconv crossing frame: what is flipped and the root fix

abconv (eic/afterburner v0.2.1 and main) gives the beams the right −25 mrad crossing, but builds the interaction point (IP) for a +25 mrad crossing. Two sign conventions cancel in the momenta; the vertex code passes through neither of them. The root fix removes both conventions and sets the presets to the ePIC angles.

Finding F2 of afterburner-workbench (dis-autoresearch F9). Numbers: 10x100 high divergence, NC DIS 10 < Q² < 100 GeV², events, written by docs/make_figure_data.py.

Coordinates and symbols

ePIC frame: the electron beam runs along −z, the proton beam leaves at θ = −25 mrad, toward −x, and +0.10 mrad vertically. The beam directions in abconv's configuration are

\[ \hat d_e = (0,\,0,\,-1), \qquad \hat d_p = R_x(\theta_v)\,R_y(\theta_h)\,\hat z = (\sin\theta_h,\; -\cos\theta_h \sin\theta_v,\; \cos\theta_h\cos\theta_v), \]

with the preset values θh = crossing_angle_hor and θv = crossing_angle_ver. Every IP6 preset sets θh = +25e-3 and θv = +100e-6, so the configured proton points to +25 mrad horizontally and −0.10 mrad vertically (rotateX(+θ) tilts +z toward −y).

Each collision comes from a proton at position p in its bunch and an electron at position e in its bunch. Both abconv and eicBeamShape set

\[ ct = \frac{e - p}{2}, \qquad z = \frac{e + p}{2} \quad\Longrightarrow\quad e = z + ct, \quad p = z - ct . \]

Λ(u) is the Lorentz transformation that gives a particle at rest the velocity u; CLHEP's HepBoost(u) is Λ(u).

What abconv does, step by step

abconv takes a head-on event (proton along +z, electron along −z) and applies, per event (Converter.cc, Afterburner.cc process_event):

1. Boost

The boost vector is half the sum of the two beam directions (Afterburner.cc lines 323–328):

\[ \vec\beta = \tfrac12(\hat d_p + \hat d_e) \approx \Big(\tfrac{\theta_h}{2},\; -\tfrac{\theta_v}{2},\; -\tfrac{\theta_h^2}{4}\Big). \]

It is applied as evt.boost(β) (Converter.cc line 84). HepMC3's GenEvent::boost(v) transforms to a frame moving with v, so it acts on the particles as Λ(−v). PR #38 states this convention in its vertex loop. With θh = +25 mrad, the momenta receive a transverse kick of −θh/2 = −12.5 mrad: toward −x.

2. Rotation

The rotation is meant to take the boosted beam axis to the beams' difference direction (lines 379–382):

\[ \hat n = (\hat d_p - \hat d_e)\times\hat z \;\propto\; (-\theta_v,\, -\theta_h,\, 0),\qquad \alpha = +\arccos\frac{(\hat d_p - \hat d_e)\cdot\hat z}{|\hat d_p - \hat d_e|} = +\frac{\theta_h}{2}. \]

For θh > 0 the axis points along −ŷ, so the rotation by +θ/2 about it is Ry(−θh/2): it turns +z further toward −x. The line carries the comment // TODO back to -acos?.

3. The two flips cancel in the momenta

The momentum transformation of v0.2.1 equals the one the ePIC geometry needs, except for the sign of the longitudinal boost component:

\[ \underbrace{R_y\!\big(-\tfrac{\theta_h}{2}\big)\,\Lambda\!\big(-\vec\beta(\theta_h)\big)}_{\text{abconv, }\theta_h = +25\text{ mrad}} \quad\text{vs.}\quad \underbrace{R_y\!\big(\tfrac{\theta}{2}\big)\,\Lambda\!\big(\vec\beta(\theta)\big)}_{\text{ePIC, }\theta = -25\text{ mrad}}, \qquad -\vec\beta(\theta_h) = \Big(\tfrac{\theta}{2},\, -\tfrac{\theta_v'}{2},\, +\tfrac{\theta^2}{4}\Big),\; \vec\beta(\theta) = \Big(\tfrac{\theta}{2},\, -\tfrac{\theta_v'}{2},\, -\tfrac{\theta^2}{4}\Big), \]

where θ = −θh and θv′ = −θv. Directions, divergences and crab kicks therefore come out right; the beams leave at −25 mrad and +0.10 mrad, the configured geometry turned by 180° about z. Only βz shows the flip, in the beam energies:

\[ \text{abconv: } \frac{\Delta E_p}{E_p} = +\frac{3\theta^2}{8} = +2.34\times10^{-4},\;\; \frac{\Delta E_e}{E_e} = -\frac{\theta^2}{8} = -0.78\times10^{-4}; \qquad \text{root fix: the two values swap.} \]

Either way the shifts add up to θ²/4, since s is invariant.

4. The vertex passes through neither flip

generate_vertx_with_bunch_interaction() (lines 54–113) is line for line eicBeamShape's. It places the collision in the bisector frame and rotates it by +θh/2 about y:

\[ x' = \sin\tfrac{\theta_h}{2}\; ct,\quad z' = \tfrac{e+p}{2} \quad\xrightarrow{\;R_y(+\theta_h/2)\;}\quad x = x'\cos\tfrac{\theta_h}{2} + z'\sin\tfrac{\theta_h}{2} \;\approx\; \frac{\theta_h}{2}\,(z + ct) + \xi_x , \]

with ξx the Gaussian luminous width. It reads θh = +25 mrad straight from the preset, and shift_position_to() sets the result without the 180° turn the momenta received. eicBeamShape runs the same formula with −0.025, so the two IPs are mirror images:

\[ \text{abconv: } x = +12.5\ \text{mrad}\times(z + ct), \qquad \text{eicBeamShape (ePIC): } x = -12.5\ \text{mrad}\times(z + ct). \]

The right sign follows from the geometry alone. With crab crossing both bunches are tilted onto the bisector of the two beams, at −θ/2 for a proton beam at −θ. An electron moving along −z keeps its x, so it collides at x = −(θ/2)·e, and e = z + ct is its position in its bunch.

Measured on the same events

All abconv rows ran on the same head-on Pythia8 file and share abconv's random numbers (the seed is fixed, F1), so their IP slopes share their noise. Pythia8's row has its own random numbers.

Negating the presets alone moves the beams to +25 mrad and flips the crab kicks, while the IP takes the ePIC sign: the IP is again opposite to the beams. Only the root fix puts every quantity on Pythia8's sign.

Root fix

Four changes, on top of PR #38 (Dmitry Kalinkin's vertex transform, D-user-4):

// cpp/abconv/Converter.cc — GenEvent::boost(-β) acts as HepBoost(+β)
-            evt.boost(FourVector(boost.x(), boost.y(), boost.z(), 0));
+            evt.boost(FourVector(-boost.x(), -boost.y(), -boost.z(), 0));

// cpp/abconv/Converter.cc — PR #38's vertex loop keeps following the momenta
-                x = CLHEP::HepBoost(-boost) * x;
+                x = CLHEP::HepBoost(boost) * x;

// cpp/afterburner/Afterburner.cc:380 — rotate +z onto the beams' difference direction
-        const double rotation_angle_to_z = acos(cos_rotation_angle_to_z);   // TODO back to -acos?
+        const double rotation_angle_to_z = -acos(cos_rotation_angle_to_z);

// cpp/afterburner/EicConfigurator.cc (all 40 presets) and the defaults in AfterburnerConfig.hh
-    cfg.crossing_angle_hor = 25e-3;
-    cfg.crossing_angle_ver = 100e-6;
+    cfg.crossing_angle_hor = -25e-3;
+    cfg.crossing_angle_ver = -100e-6;

The vertical preset changes sign too: with +100e-6 the proton would leave at −0.10 mrad. After the fix the preset, the beams, the crab kicks and the IP all use the ePIC angles:

\[ \hat d_p = (-25.0,\; +0.10)\ \text{mrad},\qquad x_{\rm IP} = \frac{\theta}{2}(z + ct) + \xi_x = -12.5\ \text{mrad}\times(z + ct) + \xi_x . \]

The crossing term in IP x is small: 12.5 mrad × 7 mm ≈ 0.09 mm at 1σ of the electron bunch, against a 0.1 mm luminous width. It matters for anything that uses the luminous-region shape or the x–t correlation of the IP, such as a collision time from the vertex.

Alternatives

  • Turn the IP, x → −x. The smallest change; the preset (+25 mrad) and the output (−25 mrad) keep opposite signs, and the energy split stays as it is.
  • Negate the presets only. No fix: the beams move to +25 mrad and the IP stays opposite to them (row "presets negated" above).
